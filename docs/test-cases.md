# 用例设计（60 条，正常 : 异常 = 42 : 18，约 7 : 3）

> 设计原则：
> 1. 每条用例**只验证一个业务规则**，失败时能直接定位；
> 2. 异常路径必须有业务含义（鉴权、参数、状态机、幂等、越权），不凑 404；
> 3. 三层断言齐全的用例打 `@pytest.mark.db`，其余至少两层；
> 4. 每条用例自己造前置数据，**不依赖执行顺序**。

## 三条断言对应关系

| 层 | 断言什么 | 代码 |
|---|---|---|
| ① HTTP | 状态码 | `expect.assert_status(resp, 200)` |
| ② 业务 | 错误码 / 关键字段 | `expect.assert_business_error(resp, http_status=422, code="...")` |
| ③ DB | 状态真的落库了 | `expect.assert_db_value(db, "select state from ... where ...", "complete", id=...)` |
